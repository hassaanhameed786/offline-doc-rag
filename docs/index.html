Chat with your documents. Offline.

A lightweight RAG pipeline that answers questions about your own files and cites its sources. It runs on your laptop with Ollama and Hugging Face embeddings, or switches to Claude with one setting.

    How it works

    Index once, then retrieve and answer for every question.

    1. Index your files

      PDF, Markdown and text files are split into overlapping chunks of about 100 words. Each chunk becomes a vector from the Hugging Face model all-MiniLM-L6-v2, saved to a local index.

    2. Retrieve the closest chunks

      Your question is embedded the same way. Cosine similarity over the index returns the four chunks closest in meaning.

    3. Generate a grounded answer

      The question and chunks go to the model with one rule: answer only from this context, cite sources, and say "I don't know" if the answer isn't there.

    4. Show the evidence

      The answer streams back with the source chunks and their scores, so you can check every claim.

    What's inside

    Seven small parts, each easy to swap.

    PartTechnologyWhat it does
    Loaderpypdf, plain file readingReads .pdf, .md and .txt files from data/
    ChunkerCustom word-based splitter100-word chunks with 20 words of overlap
    EmbedderHugging Face sentence-transformersTurns text into normalized vectors, locally and free
    Vector indexNumPyStores vectors; search is one matrix multiply
    RetrieverCosine similarity, top 4Finds the chunks most relevant to the question
    GeneratorOllama (llama3.2) or ClaudeWrites the cited answer
    InterfaceCommand lineStreams answers with sources and scores

    Design principles

    Local first
    Documents and questions stay on your machine when you use Ollama.
    Grounded answers
    The model answers from retrieved text only, cites it, and admits when it doesn't know.
    Small enough to read
    About 100 lines of core logic and no vector database, so every step is visible.
    Swappable models
    One environment variable switches between Ollama and Claude.
    Visible retrieval
    Every answer lists its source chunks and scores, which makes weak retrieval easy to spot and fix.
    Quick to respond
    The embedding model preloads at startup and answers stream word by word.

    Run it locally

    You need Python 3.10 or newer and Ollama installed.

    git clone https://github.com/hassaanhameed786/offline-doc-rag.git
cd offline-doc-rag
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
ollama pull llama3.2
python ingest.py
python chat.py
    git clone https://github.com/hassaanhameed786/offline-doc-rag.git
cd offline-doc-rag
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
ollama pull llama3.2
python ingest.py
python chat.py

    Put your .md, .txt or .pdf files in data/ before running ingest.py, and re-run it whenever they change. If Ollama isn't already running, start it with ollama serve.

    Settings live in .env: LLM_PROVIDER (ollama or anthropic), OLLAMA_MODEL, and ANTHROPIC_API_KEY if you choose Claude.

    Where it fits

    Anywhere answers must come from a specific set of documents.

    • A personal knowledge base for notes, papers and study material.
    • Questions across a set of resumes or project write-ups.
    • Search over policies, handbooks and onboarding guides.
    • Support answers drawn from FAQs and product manuals.
    • Contracts or financial files that can't be sent to a third-party API.

    The impact: less time spent searching, fewer made-up answers because every claim points to a source, no per-token cost, and private files that stay on your own machine.

    What's next

    This is single-pass RAG: it retrieves once and answers once. These are the planned upgrades.

    • FastAPI service with ingest and ask endpoints
    • Web interface with Streamlit or Gradio
    • Evaluation script for hit rate and faithfulness
    • Heading-aware chunking
    • Hybrid search and re-ranking
    • FAISS or Chroma for larger collections
    • Conversation memory for follow-up questions
    • Agentic retrieval with query rewriting
